# 헤더 탭 드래그 화면 분할 계획

- 작성: 2026-10-18
- 상태: 범위 확정 / 구현 진행
- 요청: 헤더 탭을 콘텐츠 오른쪽·아래·왼쪽으로 드롭해 여러 탭을 중첩 분할로 동시에 표시하고, 새로고침·재로그인 후에도 분할 상태 유지.
- 참고: 사용자가 첨부한 Obsidian 화면의 분할 방식. 사용자의 후속 확인에 따라 3개 이상 중첩 분할을 이번 범위에 포함한다.

## 1. 범위와 기본 결정

문서 탭을 3개 이상 중첩 분할하여 동시에 표시한다. 2개 영역으로 제한하지 않는다. 좌우 또는 상하 분할을 제공하며, 각 영역은 자체 탭 목록·활성 탭·툴바·스크롤·편집/미리보기 모드를 가진다. 기존 좌측 탐색과 우측 정보 패널은 공유한다.

영속성의 기본 범위는 **같은 브라우저의 동일 계정·동일 워크스페이스**다. 로그아웃은 레이아웃을 삭제하지 않으며 같은 계정으로 로그인하면 복원한다. 다른 기기/브라우저 동기화와 브라우저 데이터 삭제 후 복구는 이번 범위에서 제외한다. 이 범위에는 사용자별 localStorage 저장으로 충분하며 DB migration은 필요 없다. 계정 간·기기 간 동기화까지 요구가 확대되면 별도 사용자 설정 API/DB 모델로 설계를 확장한다.

구분선 드래그 크기 조절과 키보드 메뉴를 제공한다. 같은 문서의 복제 편집과 Graph/Folder를 분할 탭으로 전환하는 작업은 제외한다.

## 2. 드롭 동작 계약

예시는 현재 활성 문서 A와 다른 헤더 탭 B가 열린 상태에서 B를 드래그하는 경우다. 드래그 시작만으로 활성 탭을 B로 변경하지 않고, 시작 시점의 활성 A를 기억한다.

| 드롭 위치 | 결과 | 포커스 |
| --- | --- | --- |
| 콘텐츠 오른쪽 가장자리 | 왼쪽 A / 오른쪽 B | B |
| 콘텐츠 왼쪽 가장자리 | 왼쪽 B / 오른쪽 A | B |
| 콘텐츠 아래 가장자리 | 위 A / 아래 B | B |
| 같은 영역 중앙·위쪽·바깥 / Escape | 변경 없음 | 이전 상태 |

- 탭은 복제하지 않고 이동한다. B 이외의 탭은 기존 그룹의 순서대로 유지한다.
- 현재 활성 탭 A 자체를 드래그하면 A는 드롭한 영역으로 이동하고, 기존 그룹에서는 인접 탭을 활성화한다(오른쪽 우선, 없으면 왼쪽). 다른 탭이 없으면 분할을 시작하지 않고 안내한다.
- 빈 새 탭은 첫 버전에서 분할 드래그 대상에서 제외한다. 분할된 각 영역의 `+`로 빈 탭을 여는 동작은 지원한다.
- 대상 영역 가장자리 드롭은 그 영역만 새 split 노드로 교체하고, 다른 영역 중앙 드롭은 해당 그룹으로 탭을 이동한다. 중앙 이동 시 대상 그룹의 기존 활성 문서는 비활성 탭으로 남는다. 같은 그룹 중앙 드롭은 변경하지 않는다.
- 그룹 간 이동으로 원래 그룹이 비면 해당 leaf를 제거하고 형제 subtree가 부모 공간을 차지한다. 다른 분기와 탭은 유지한다. 분할 방향 전환은 해당 split의 좌우/상하 전환으로 제공한다.
- 드래그 중에만 반투명 배치 미리보기를 표시한다. 좌우 가장자리 25%, 아래 25%를 초기 판정값으로 하고, 아래 모서리는 아래 드롭을 우선한다. 최종 폭은 실제 화면 검증 후 조정한다.
- 헤더 클릭은 탭 선택, 일정 거리 이동 후 드래그 시작으로 구분한다. 닫기·추가 버튼에서는 드래그를 시작하지 않는다. 외부 파일/문자열 드롭은 이 동작으로 처리하지 않는다.

## 3. 분할 후 사용 규칙

- 각 split의 초기 비율은 50:50. split별 구분선을 움직여 해당 두 하위 영역의 비율을 바꾸고 독립 저장한다.
- 제안 최소 크기는 영역당 폭 320px / 높이 240px. 중첩 트리에서 필요한 최소 작업 공간 크기를 계산하고 중앙 작업 공간에 스크롤을 제공하여 모든 영역을 유지한다.
- 활성 영역은 클릭 또는 키보드 포커스 진입으로 바뀐다. 탭 강조와 영역 경계로 현재 작업 대상을 구별한다.
- 탐색 목록·검색·위키 링크에서 문서를 열면 활성 영역에서 연다. 다른 영역에 이미 열린 문서라면 해당 영역으로 포커스를 이동해 중복 편집을 피한다.
- 우측 개요·첨부파일·버전·감사 로그는 각 영역에서 표시 중인 문서를 문서명별 접기/펼치기 목록으로 함께 표시한다. 세부 동작은 아래 우측 사이드바 계약을 따른다. Workspace AI의 selected document는 활성 영역을 따른다. 문서별 Ask AI는 각 문서에 귀속하며 저장된 본문만 사용한다.
- 한 영역의 탭을 닫으면 그 그룹 안에서 다음 탭을 선택한다. 마지막 탭을 닫으면 해당 leaf를 제거하고 형제 subtree가 부모 공간을 차지한다. 전체 마지막 탭은 기존 빈 화면 동작을 따른다.
- `분할 해제`는 모든 다른 그룹의 탭을 트리 순서대로 활성 그룹 뒤에 합쳐 단일 영역으로 만든다. 문서나 미저장 편집을 삭제하지 않는다.
- Graph/Folder 진입은 임시 단일 화면으로 표시하고 문서 분할 상태를 보존한다. 문서로 돌아오면 복원한다.
- 탭 메뉴에 `왼쪽으로 분할`, `오른쪽으로 분할`, `아래로 분할`, 분할 중 `다른 영역으로 이동`, `분할 해제`를 제공해 드래그 없이도 같은 동작을 수행한다. 구분선은 키보드 크기 조절과 접근 가능한 이름을 제공한다.

### 우측 사이드바: 문서별 접기/펼치기

개요·첨부파일·버전·감사 로그의 기존 카테고리 선택 방식은 유지하고, 각 카테고리 콘텐츠를 **문서명 헤더 + 해당 문서 콘텐츠**의 목록으로 구성한다. 모든 분할 영역에서 표시 중인 문서를 나열하며, 포커스 이동만으로 한 문서의 목록이 사라지지 않는다. 그룹의 비활성 탭 전체는 나열하지 않는다.

```text
우측 사이드바 / 개요
  ▾ 문서 A
      제목 1
      제목 2
  ▸ 문서 B

우측 사이드바 / 첨부파일
  ▸ 문서 A
  ▾ 문서 B
      image.png
      guide.pdf
```

- 네 카테고리 모두 동일한 문서별 헤더/화살표 패턴을 적용한다. 문서명 헤더 전체를 버튼으로 사용하고 `▸`는 접힘, `▾`는 펼침을 나타낸다. 여러 문서를 동시에 펼칠 수 있다.
- 헤더 클릭은 해당 콘텐츠만 접거나 펼친다. 문서 선택·활성 영역·URL을 바꾸지 않는다. 포커스된 문서는 별도 강조로 표시한다.
- 문서 목록 순서는 트리를 좌→우/위→아래로 순회한 leaf 순서다. 제목이 같으면 경로를 보조 표시하고, 상태 식별은 제목이 아닌 document ID를 사용한다. 제목 변경은 목록에 즉시 반영한다.
- 최초 표시 시 문서별 콘텐츠는 기본 펼침으로 표시한다. 이후 접힘/펼침은 **문서 ID × 카테고리**별로 독립 유지한다. A의 개요를 접어도 B의 개요나 A의 첨부파일은 바뀌지 않는다.
- 카테고리 전환, 영역 포커스 전환, 문서의 영역 간 이동, 사이드바 닫기/다시 열기는 접힘 상태를 초기화하지 않는다. 새로고침·동일 계정 재로그인 때도 복원한다.
- 각 영역에서 탭을 바꾸면 해당 위치의 문서 목록만 교체한다. 분할 해제 후에는 단일 영역의 표시 문서 하나를 같은 헤더 패턴으로 보여준다. Graph/Folder나 빈 탭처럼 문서가 아닌 영역은 문서 목록에서 제외한다. 대상 문서가 없으면 안내를 표시한다.
- 개요 항목을 누르면 **그 개요가 속한 문서의 영역**을 활성화하고 해당 제목으로 스크롤한다. 현재 포커스된 다른 문서로 스크롤하면 안 된다.
- 첨부파일 열기/업로드/삭제, 버전 조회/복원은 **해당 문서 헤더 아래의 문서 ID**를 대상으로 수행한다. 쓰기 권한과 복원 확인은 문서별로 적용하며, 다른 영역의 draft를 초기화하지 않는다. 감사 로그도 문서별 조회 결과를 분리한다.
- 각 문서 그룹은 로딩·오류·빈 상태를 독립 표시한다(개요 없음 / 첨부파일 없음 / 버전 없음 / 감사 로그 없음). 한 문서 조회 실패로 다른 문서 콘텐츠를 숨기지 않는다. 삭제·권한 회수된 문서의 헤더와 콘텐츠는 제거한다.
- 헤더는 `aria-expanded`, `aria-controls`가 연결된 버튼으로 구현하고 Enter/Space로 토글한다. 접힌 콘텐츠는 키보드 포커스 대상에서 제외하며, DOM ID는 카테고리와 문서 ID를 포함해 중복을 방지한다.

## 5. 상태와 저장 구조

제안 키: `munjib:workspace-layout:<userId>:<workspaceId>:v1`.

```ts
type LayoutNode = {
  type: 'pane';
  id: string;
  activeTabId: string | null;
  tabs: Array<{ id: string; documentId: string | null }>;
} | {
  type: 'split';
  id: string;
  direction: 'horizontal' | 'vertical';
  ratio: number; // 첫 child 비율, 각 child의 최소 크기로 제한
  children: [LayoutNode, LayoutNode];
};

type WorkspaceLayout = {
  version: 1;
  root: LayoutNode;
  activePaneId: string;
  rightSidebar: {
    expandedByDocument: Record<string, Partial<Record<
      'outline' | 'attachments' | 'versions' | 'audit', boolean
    >>>; // 키는 documentId, 누락 값은 기본 펼침
  };
};
```

- 레이아웃에는 ID·순서·방향·비율·활성 선택·우측 사이드바의 문서별/카테고리별 펼침 여부만 저장한다. 본문, 제목, 권한, 인증 정보는 저장하지 않는다. 제목은 현재 읽기 가능한 문서 목록에서 계산한다.
- 사이드바 펼침 상태는 같은 계정/workspace layout 키에 저장한다. 문서가 닫혔다 다시 열릴 때도 재사용하되, 현재 읽기 가능한 문서 목록에서 삭제·권한 상실이 확인된 ID는 제거한다. 잘못된 타입과 알 수 없는 카테고리는 무시한다.
- reducer가 이동·분할·합치기·닫기를 한 번의 상태 전이로 처리하고 최종 snapshot 하나를 저장한다. 중복 탭 ID, 잘못된 활성 참조, 잘못된 비율, 빈 그룹을 정규화한다.
- 서버 렌더 초기값과 클라이언트 첫 렌더는 일치시킨다. 사용자/워크스페이스 식별 및 hydration 이후 복원하고, 복원 완료 전 기본값을 저장하지 않는다.
- 현재 읽기 가능한 문서 ID로 모든 저장 탭을 다시 검증한다. 삭제·권한 제거 문서는 제외하고, 빈 그룹을 제거하고 단일 child가 된 split을 축약한다. 문서가 하나도 없으면 빈 단일 영역으로 복원한다. 접근 불가 문서의 제목/본문을 이전 캐시에서 표시하지 않는다.
- 저장소 차단·용량 초과·깨진 JSON·알 수 없는 버전이면 안전한 단일 레이아웃으로 시작한다. 저장 실패 시 현재 세션에서는 사용 가능하되 `레이아웃을 저장하지 못했습니다`를 한 번 안내한다.
- legacy 키는 계정 식별자가 없으므로 소유자를 증명할 수 없는 기존 상태를 자동 이관하지 않는다. 신규 키가 없으면 현재 URL 문서에서 시작한다. 기존 키를 다른 계정의 신규 키로 복사하지 않는다.
- 로그아웃 시 화면 메모리와 요청 캐시는 초기화하되 해당 계정의 layout 키는 보존한다. Trial은 계정 키와 공유하지 않으며 첫 버전 분할 지원은 인증 workspace로 한정한다.
- 여러 브라우저 탭에서는 외부 storage 변경으로 편집 중 화면을 자동 재배치하지 않는다. 마지막으로 레이아웃을 변경한 창의 snapshot을 다음 진입 때 사용한다. 단순 조회·복원은 저장하지 않는다.
- 새로고침/재로그인 시 저장된 문서 버전을 조회한다. 레이아웃 복원은 미저장 본문 복구를 의미하지 않는다.

## 6. 렌더링·라우팅·편집 경계

1. `WorkspaceLayoutProvider`가 레이아웃과 활성 영역을 소유하고 트리의 각 leaf에 `WorkspacePane`을 렌더링한다. pane마다 view-mode provider·toolbar·scroll·history를 둔다.
2. 현재 page의 문서 상세 조회를 공통 서버 loader로 추출한다. 세션, workspace membership, 문서 read/write 권한 검증을 유지하고, 두 번째 영역도 같은 loader를 사용하는 인증 endpoint로 읽는다. 클라이언트 ID나 저장 레이아웃은 권한 근거가 아니다.
3. URL의 `?document=`는 포커스된 문서를 표현한다. 명시적 링크 진입은 복원 레이아웃의 활성 영역에 적용하며, 이미 다른 영역에 열린 문서면 그쪽을 선택한다. 명시적 URL이 없으면 저장된 활성 선택을 따른다.
4. 영역 포커스 변경은 URL replace, 새 문서 탐색은 push를 기본으로 한다. 브라우저 뒤로/앞으로는 대상 문서를 선택하되 분할을 없애지 않는다. URL 동기화와 storage 복원이 서로 반복 실행되지 않게 전이 출처를 구분한다.
5. 탭 이동 때 편집기를 remount해 draft를 잃지 않도록 탭 ID 기준의 편집 세션을 상위에서 유지한다. draft·selection·스크롤과 pending 이미지 업로드의 소유권도 탭/문서에 고정한다. 구현 시 editor 내부 상태와 DOM id, 저장 shortcut, focus listener를 먼저 감사한다.
6. 저장·붙여넣기·AI·metadata 요청은 각 문서 ID에 귀속한다. 활성 영역 변경 후 늦게 도착한 응답이 다른 문서를 덮어쓰지 않도록 요청 취소 또는 generation 검사를 둔다.
7. 양쪽 편집 중 한쪽 저장/refresh가 반대쪽 draft를 초기화하지 않아야 한다. dirty 탭 닫기·로그아웃·새로고침은 저장/취소/나가기 보호 흐름을 점검한다. 이동 자체에는 draft 폐기 확인을 요구하지 않는다.
8. 우측 사이드바에는 단일 selectedDocument 대신 영역 순서의 표시 문서 목록과 문서별 metadata를 전달한다. 네 카테고리는 공통 문서 헤더/접기 컴포넌트를 사용하고, 개요 탐색은 documentId→paneId 매핑으로 올바른 스크롤 컨테이너를 찾는다. 조회·mutation·오류·캐시는 문서 ID로 분리하며 활성 영역 변경만으로 요청 대상을 치환하지 않는다.

## 7. 구현 순서

### 구현 전 코드 검토에서 발견한 보완 사항 (2026-10-18)

- `components/app-shell.tsx`의 개요 등록은 단일 navigator/outlineDocument다. 문서별 등록과 해제 구조가 필요하며, 한 편집기의 unmount가 다른 문서 등록을 지우지 않아야 한다.
- `lib/outline-targets.ts`는 전체 document에서 첫 heading을 찾는다. 서로 같은 제목을 가진 두 문서에서도 정확히 이동하도록 문서/영역 컨테이너 안으로 검색을 제한한다.
- `components/document-editor.tsx`는 서버에서 받은 문서 ID·제목·본문 변경 시 로컬 draft를 초기화한다. 서버 갱신과 미저장 수정이 겹치면 자동 덮어쓰지 않고 문서별 dirty 상태를 비교해야 한다. 다른 문서의 저장이 모든 draft를 초기화하는 경로를 회귀 테스트한다.
- CodeMirror 인스턴스, undo/selection, 이미지 붙여넣기 pending 상태는 편집기 내부에 있다. 탭 이동 시 부모를 바꿔 remount하지 않도록 공통 host에서 안정적인 탭 key와 CSS 배치를 사용하고, 탭 비활성화 중에도 작업 세션을 유지하는 구조를 우선 검토한다.
- 최신 main에서 첨부 업로드는 attachmentId를 반환한다. 버전 복원 server action은 문서 URL로 redirect한다. 분할 환경에서는 작업 문서의 데이터만 갱신하고 반대 영역을 치환하지 않는 응답 경로가 필요하다. 기존 단일 화면/Trial 호출 계약도 회귀 검증한다.
- 현재 체크아웃은 이미 병합된 README 작업 브랜치이며 별도 미커밋 문서 변경이 존재한다. 구현은 최신 main 기반 별도 worktree에서 수행하고 이 계획 문서만 가져온다.
